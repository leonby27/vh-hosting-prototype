# Подчёркивание текста

По умолчанию не подчёркивайте текст и ссылки, в том числе при наведении и фокусе. Используйте подчёркивание только по явной просьбе пользователя.

# Визуальная проверка

Визуальную проверку интерфейса выполняет пользователь. Не открывайте превью и не делайте скриншоты для оценки внешнего вида без явной просьбы пользователя.

# Выпадающие меню

Для всех выпадающих меню и панелей выбора поверх страницы используйте `DropdownPanel` из `src/hosting-motion.jsx`. Передавайте в него `open` и связывайте кнопку с панелью через `aria-expanded` и `aria-controls`. Оставляйте панель в DOM при закрытии, чтобы проигрывалась общая анимация. Компонент сам блокирует взаимодействие с закрытой панелью и учитывает настройку уменьшенного движения через общие стили.

Задавайте расположение и оформление панели в стилях раздела. Для панели, открывающейся вверх, задавайте `--hosting-menu-offset: 8px`.

# Анимация блоков в потоке страницы

Для условных блоков, которые сдвигают соседний контент, используйте `AnimatedBlock` из `src/hosting-motion.jsx`. Держите обёртку в DOM и передавайте условие через `open`. Она анимирует раскрытие, закрытие и изменение высоты содержимого. Отступы, которые должны исчезать вместе с блоком, задавайте внутри обёртки.

Для появления статичных карточек и секций при входе на экран используйте общий класс `hosting-reveal`. При реализации интерактивных блоков учитывайте появление, исчезновение и изменение содержимого. Соседние секции должны двигаться плавно, а при `prefers-reduced-motion: reduce` состояние должно меняться сразу.

# Закрытие модальных окон

По умолчанию клик по фону закрывает модальное окно. Если закрытие приведёт к потере несохранённых изменений или введённых данных, передавайте `closeOnBackdrop={false}` в `Dialog` или `ModalFrame` на время этих изменений. После возврата к исходным значениям клик по фону снова закрывает окно. Крестик, явная отмена и Escape используют обычный для окна сценарий закрытия.

# Иллюстрации модальных окон

Для новых иллюстраций по умолчанию используйте как референс [сервер со стрелкой переноса](src/assets/tariff-settings/server-transfer.png). Сюжет выбирайте по смыслу окна. Собирайте его в компактную композицию с одним главным объектом и, при необходимости, одним знаком действия. Центрируйте композицию по видимому силуэту и проверяйте читаемость в размере 80 × 80 px.

Используйте объёмный 3D-ракурс, умеренные скругления и мягкие фаски. Ориентируйтесь на приглушённый стальной синий, более тёмные синие тени и светло-голубые блики, как у [антивируса](src/assets/antivirus/service-icon-blue.png) и [DDoS-защиты](src/assets/network-protection/service-icon-blue.png) во вкладке «Другие сервисы». Основной знак действия может быть белым. Избегайте игрушечных форм, резкой угловатости и яркого глянца.

Экспортируйте квадратный PNG с прозрачным фоном. По большей стороне видимый силуэт должен занимать около 90% холста, то есть примерно 72 px во фрейме 80 × 80 px. Оставляйте поля визуально равномерными, сохраняйте пропорции объекта, без обрезанных краёв. Выравнивайте заполнение прозрачными полями самого PNG. Передавайте иллюстрацию через `illustration` общего `Dialog`, где уже задан фрейм 80 × 80 px.

# Поддержка дизайн-системы

При работе над интерфейсом сначала проверьте общие компоненты в `src/ui/index.js` и существующие примеры в `src/design-system/`. Используйте подходящий общий компонент и его существующие варианты. Отступы, раскладку и оформление, привязанное к конкретному экрану, оставляйте в этом экране.

Не добавляйте самостоятельно кастомные стили к компонентам, которые уже есть в дизайн-системе. Переопределять их оформление, размеры, внутренние отступы, состояния или анимации через локальные классы, CSS-селекторы, inline-стили, токены или обёртки разрешено только по явной просьбе пользователя. Общая просьба реализовать интерфейс не является таким разрешением. Используйте существующие параметры и варианты компонента. Стили экрана могут задавать раскладку и внешнее расположение компонентов, но не менять их собственное оформление или поведение. Не обходите это правило сборкой локальной замены из внутренних частей общего компонента. Если существующих возможностей недостаточно, сначала согласуйте изменение с пользователем.

Точечно менять существующий общий компонент можно в рамках согласованной задачи. В существующем примере отражайте только изменения, относящиеся к этой задаче.

Создавайте новые страницы проекта, включая страницы и разделы каталога дизайн-системы, только по прямой просьбе пользователя. То же правило действует для новых вариантов, демонстрационных блоков и примеров в дизайн-системе. Использование компонента на другом экране, изменение общего стиля или добавление параметра сами по себе не дают оснований расширять каталог. Не дублируйте существующие примеры.

Общие размеры, отступы и состояния задавайте в общей реализации компонента или его токенах. Вложенные применения используют те же компоненты и варианты. Так, строки в селекте, обычном дропдауне и меню шапки получают отступы и состояния из общей строки меню. Стили страницы задают расположение меню, а отличия в оформлении строки выражаются явным вариантом общего компонента.

Если пользователь указал конкретный экран или место, но из задачи неясно, нужно ли менять общий компонент, создать отдельный вариант или внести локальную правку, сначала уточните охват. Само упоминание экрана не определяет охват изменения.

Начинайте вести Changelog только после явной команды пользователя. До неё оставляйте `src/design-system/changelog.js` пустым. После команды записывайте только последующие изменения общих компонентов и их токенов, которые меняют состояние дизайн-системы на момент старта. Указывайте дату, компонент и что изменилось. Ссылку ведите на соответствующий раздел каталога. Для изменений одной страницы и внутренних переработок без видимого эффекта запись не нужна.

Поддержку светлой и тёмной тем, состояний и размеров задавайте в общем компоненте. При оформлении блоков каталога сплошной фон означает `Base/On Background` без обводки, а фон с рамкой означает `Base/Background` с обводкой.
